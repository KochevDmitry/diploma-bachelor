# Архитектура решения для работы с картой

## Выбор API карт

После анализа документации **2GIS MapGL** и **Yandex Maps API**, выбран **Yandex Maps API** по следующим причинам:

1. **Простота интеграции** - более простой API для базовых задач
2. **Документация** - отличная документация на русском языке
3. **Маркеры и клики** - удобная работа с событиями клика на маркеры
4. **Бесплатный тариф** - достаточный для разработки и тестирования

## Подход к работе с площадками

### Принцип работы

1. **Площадки хранятся в базе данных** (PostgreSQL + PostGIS)
   - Координаты (широта/долгота) в формате PostGIS Geography
   - Адрес, название, тип спорта
   - Все площадки предварительно добавлены в БД

2. **Карта отображает все площадки**
   - При загрузке страницы запрашивается список всех площадок через API
   - На карту автоматически размещаются маркеры для каждой площадки
   - Маркеры подсвечиваются и имеют иконки спорта

3. **Взаимодействие пользователя с картой**
   - Пользователь кликает на маркер площадки
   - Система получает ID площадки
   - Запрашиваются активные игровые сессии для этой площадки
   - Показывается боковая панель с информацией

4. **Создание и присоединение к играм**
   - Если на площадке нет активных игр - пользователь может создать новую
   - Если есть активные игры - пользователь может присоединиться
   - Все изменения отображаются в real-time через WebSocket

### Преимущества подхода

- ✅ **Не нужно добавлять объекты в саму карту** - все данные на нашей стороне
- ✅ **Полный контроль** над данными о площадках
- ✅ **Быстрый поиск** через PostGIS индексы
- ✅ **Кеширование** в Redis для производительности
- ✅ **Масштабируемость** - легко добавить новые площадки через API

### Альтернативный подход (не используется)

Можно было бы использовать встроенные функции карты для добавления объектов, но это:
- ❌ Ограничивает контроль над данными
- ❌ Сложнее синхронизировать с БД
- ❌ Меньше гибкости для будущих функций

## Технические детали

### Хранение координат

```sql
-- Используется PostGIS Geography тип
location GEOGRAPHY(Point, 4326)

-- Индекс для быстрого поиска
CREATE INDEX venues_location_idx ON venues USING GIST(location);
```

### Поиск поблизости

```python
# Поиск площадок в радиусе (пример из Map Service)
point = ST_Point(lon, lat, srid=4326)
query = db.session.query(
    Venue,
    ST_Distance(Venue.location, point).label('distance')
).filter(
    ST_Distance(Venue.location, point) <= radius * 1000
)
```

### Кеширование

- Список всех площадок кешируется в Redis на 5 минут
- Активные сессии кешируются на 30 секунд
- При изменении данных кеш автоматически очищается

## Интеграция с Yandex Maps

### Загрузка API

```javascript
// Динамическая загрузка скрипта с API ключом
const script = document.createElement('script');
script.src = `https://api-maps.yandex.ru/3.0/?apikey=${API_KEY}&lang=ru_RU`;
```

### Создание маркеров

```javascript
const marker = new window.ymaps.Placemark(
  [lat, lon],
  {
    balloonContent: `<strong>${name}</strong><br>${address}`,
    iconCaption: name
  },
  {
    preset: 'islands#sportIcon'
  }
);
```

### Обработка кликов

```javascript
marker.events.add('click', () => {
  onVenueSelect(venue); // Передача данных о площадке
});
```
